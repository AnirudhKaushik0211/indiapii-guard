# Evaluation history

Held-out discipline (SPEC 9.9): the held-out and adversarial templates were written and frozen before any run on them. After held-out run 1 the detector changes only to fix a defect first reproduced by a unit test, a dev document or an adversarial document. At most 3 held-out runs before release v1.0.0. Re-runs with an unchanged detectorHash and unchanged template hashes are notes under the existing entry, not new runs. File hashes use `fileHash` from `eval/report.cjs` (CRLF to LF, BOM stripped).

## 2026-11-13 - held-out run 2: dev and adversarial fixes for G05, G10 and G21
- Detector change since the previous held-out run: four rule changes in `js/lexicon.js` and `js/detector.js`, each a deviation from the v1.2 SPEC (sections 3.6 and 3.7); base scores, boosts, penalties, windows, thresholds and the gate are unchanged. (1) `NEG_NUMERIC` gains the Devanagari word for "order" (U+0911 U+0930 U+094D U+0921 U+0930). (2) `NEG_NUMERIC` gains "complaint". (3) The UPI context lexicon gains the payment words "pay", "paid", "settlement", "bhej" and "bhejo"; UPI context affects only UPI candidates. (4) When a negative phrase counts before a candidate, an own-context phrase after the candidate no longer counts (it labels the next value); own context before the candidate still counts together with the negative phrase, as in the SPEC 3.7 table. Unit tests: four "deviation:" cases in `test/detector.test.cjs`.
- Reason: owner decision to attempt G05/G10/G21 fixes using only dev and adversarial data. (1) dev d-neg-11 (for example dev-0015): Devanagari order numbers reported as CARD (17 dev CARD false positives). (2) adversarial a-neg-11 (for example adversarial-0009): complaint numbers reported as PHONE (12 decoy hits). (3) dev d-payments-02 (for example dev-0006), adversarial a-payments-03 (adversarial-0130) and a-chat-04 (adversarial-0035): unknown-handle UPI IDs after "Pay ... to", "Settlement to" or before "... bhej" scored 0.45 and were missed. (4) adversarial a-chat-02 (adversarial-0031) and a-chat-03 (adversarial-0032): order16 and utr12 decoys took the card or Aadhaar label of the following value (22 decoy hits). No rule is keyed to a held-out document, string, seed or template, and each rule is justified only by the cited dev and adversarial documents. Held-out run 1 per-entity results and failure examples (published in docs/EVAL-REPORT.md) and the build review's diagnosis of held-out decoy and context-phrasing errors were visible when the failing criteria were chosen for work, and some of the new phrases also occur in held-out templates, so held-out run 2 is not fully blind.
